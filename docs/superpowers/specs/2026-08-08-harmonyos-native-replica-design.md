# MILO HarmonyOS 原生复刻设计

## 目标

使用 ArkTS、ArkUI 和 Stage 模型开发 MILO 的 HarmonyOS 原生版本。现有 Web MVP 是产品功能、视觉、文案和交互的唯一基准；本项目不新增产品功能，也不重新设计已有流程。

交付范围包括：情绪选择、现在/过去分流、模糊时间、AI 引导对话、脚本降级、第一人称日记、原生持久化、时间线、详情、语音输入、触觉反馈、分享卡片、MiniMax AI 网关、测试与上架准备。

## 硬约束

- 客户端必须是 ArkTS + ArkUI 原生应用，不嵌入现有 Web 应用，也不使用 WebView 承载核心页面。
- 页面结构、中文文案、状态转换、情绪分类、情绪顺序和交互反馈以 `apps/web` 为准。
- 已有图片和图标必须直接复用原文件，不生成、不重绘、不擅自替换。
- 图片仅允许做 HarmonyOS 资源目录所需的无损复制、文件命名调整和资源索引。
- MiniMax 密钥不得写入客户端、源码或 Git，只通过服务端环境变量注入。
- AI、语音或网络不可用时，用户仍能完成记录、保存和回看流程。
- 当前未提交的 Web monorepo 迁移改动属于既有工作，本项目不得覆盖或清理它们。

## 选型

采用模块化 ArkUI 原生实现。相比单模块快速复刻，它能隔离页面、领域状态、持久化和系统能力；相比 WebView，它符合原生开发目标，并降低系统能力、性能和审核的不确定性。

客户端使用 HarmonyOS Stage 模型。服务端沿用仓库现有 Node 生态，使用 TypeScript 实现独立 AI 网关。客户端与服务端通过版本化 HTTPS API 通信；流式输出作为实现目标，连接失败时回退到本地脚本。

## 仓库布局

```text
apps/
  web/                         # 现有 Web 产品和行为基准
  harmony/                     # ArkTS + ArkUI Stage 模型客户端
    entry/src/main/ets/
      pages/                   # 页面与导航容器
      features/
        mood/                  # 情绪转盘和情绪星球
        recall/                # 现在/过去分流与时间标记
        conversation/          # AI 与脚本引导
        diary/                 # 日记编辑与保存
        timeline/              # 时间线与详情
        share/                 # 分享卡片
      core/
        model/                 # 领域模型与流程状态
        data/                  # 原生持久化
        network/               # AI 网关客户端
        system/                # 语音、触觉、权限和分享
    entry/src/main/resources/  # 复用资产与本地化文案
services/
  ai-gateway/                  # MiniMax 网关
docs/
  compliance/                  # 数据流、权限矩阵与审核清单
```

ArkTS 对 TypeScript 的兼容存在约束，因此不承诺让 Web 与 HarmonyOS 直接引用同一份源文件。共享内容首先定义为稳定的数据契约和测试样例，再分别用 TypeScript 与 ArkTS 实现，避免工具链耦合。

## 页面和状态流

原生应用复刻以下现有流程：

```text
首页情绪转盘
  -> 现在 / 过去
     -> 当下速记 -> 保存
     -> 模糊时间 -> AI/脚本引导 -> 第一人称日记 -> 保存/分享
时间线 -> 日记详情
```

页面和行为映射如下：

| Web 基准 | HarmonyOS 功能 | 验收重点 |
| --- | --- | --- |
| `Home.tsx` | 情绪首页 | 星球资产、滑动方向、选中态、确认入口 |
| `Classify.tsx` | 来源分流 | 现在/过去选择与返回行为 |
| `NowNote.tsx` | 当下速记 | 情绪继承、输入、保存 |
| `PastTime.tsx` | 模糊时间 | 文案、输入与下一步状态 |
| `Chat.tsx` | 引导对话 | 流式文本、语音、脚本降级、异常恢复 |
| `Diary.tsx` | 日记 | 第一人称草稿、编辑、保存 |
| `Card.tsx` | 分享卡片 | 排版、图片生成、保存与系统分享 |
| `Timeline.tsx` | 时间线 | 顺序、摘要、空状态 |
| `Detail.tsx` | 日记详情 | 完整内容与导航 |

首轮以手机竖屏和 Web 移动视口为视觉基准。安全区、系统字体缩放、软键盘遮挡和页面恢复属于原生必验项；这些适配不得改变正常字号下的基准视觉层级。

## 视觉和资产

情绪星球原始透明 PNG 位于 `docs/superpowers/concepts/mood-orbs/`。HarmonyOS 工程直接复制这五张三联图并沿用现有裁切规则，对应十五种情绪；不得从 `dist` 构建产物反向提取。

代码生成的视觉不属于图片资产。星空、玻璃质感、光晕和转场使用 ArkUI 绘制、动画或平台图形能力进行等价复刻。实现优先级为：布局与资产一致、手势和状态一致、转场节奏一致、装饰效果一致。若平台渲染机制不同，以目标设备上的可见结果和性能为验收标准。

每个关键页面保存 Web 移动视口基准截图，并为 HarmonyOS 模拟器和真机生成对应截图。视觉差异必须显式记录；不能以重新生成资产消除差异。

## 数据模型和持久化

领域模型至少包含：

- `Mood`：情绪 ID、标签、分类、顺序和资产引用。
- `ConversationMessage`：角色、内容、时间和来源（AI 或脚本）。
- `DiaryEntry`：ID、情绪、来源、模糊时间、对话、日记正文、创建与更新时间。
- `RecallSession`：当前流程状态、临时输入和恢复信息。

浏览器 `localStorage` 替换为 ArkData 原生持久化。保存日记是本地事务，不依赖 AI 或分享成功。应用被终止或进入后台后，已确认的用户输入和日记不得丢失。首版无账号、无跨端同步，保持 Web MVP 的产品边界。

## 系统能力替换

| Web 能力 | HarmonyOS 替换 |
| --- | --- |
| Web Speech API | HarmonyOS 可上架的语音识别能力 |
| Vibration API | 系统触觉反馈 |
| Canvas 2D PNG | 原生 Canvas/PixelMap 图片输出 |
| 浏览器下载/分享 | 文件保存与系统分享面板 |
| `localStorage` | ArkData 原生持久化 |
| 浏览器 WebSocket ACP | 版本化 HTTPS AI 网关接口 |

权限按功能触发：用户点击语音输入时才申请麦克风权限；拒绝权限后保留文字输入并给出可恢复说明。分享卡片生成失败不能影响日记保存。

## AI 网关

请求路径如下：

```text
HarmonyOS App
  -> MILO AI Gateway
     -> 鉴权、限流、输入约束、超时和日志脱敏
     -> MiniMax OpenAI-compatible chat completions API
  -> 流式回复或结构化错误
  -> 客户端失败时启用本地脚本
```

服务端配置：

- `MINIMAX_API_KEY`：必需，真实值由用户在部署环境配置。
- `MINIMAX_BASE_URL`：默认 MiniMax 官方 API 地址。
- `MINIMAX_MODEL`：模型 ID，可部署时切换，不写死在客户端。
- `PORT`、请求超时、单会话消息数和限流阈值：均由环境变量配置并提供安全默认值。

网关使用 MiniMax 当前 OpenAI 兼容的 `/v1/chat/completions` 接口，不使用已废弃的 `chatcompletion_v2`。它迁移 `apps/web/src/lib/guide.ts` 中的引导身份、阶段目标、日记生成规则和输出约束。

网关不持久化完整日记或对话。运维日志只记录请求 ID、耗时、状态和脱敏错误；不得记录用户正文、Authorization 请求头或 API 密钥。输入和输出命中供应商敏感标记、返回为空、超时、断网、限流或流中断时，客户端展示可恢复状态并切换脚本流程。

## 脚本降级

脚本降级迁移现有 `FallbackGuide` 的完整步骤和本地日记模板，并保持相同语气。降级可在以下时机触发：

- 应用启动后检测到无网络；
- 网关连接或首段响应超时；
- 网关返回不可重试错误；
- 流式输出中断且无法安全续传；
- 用户主动选择继续离线流程。

已经收到的 AI 内容保留在会话中，后续脚本不得重复询问已完成阶段。降级状态随会话持久化，恢复页面后继续原路径。

## 错误处理

- 网络错误：短暂错误允许有限重试，随后进入脚本，不阻塞保存。
- 存储错误：保持编辑内容在内存并明确提示重试，不宣称保存成功。
- 权限拒绝：关闭对应系统能力，保留文字输入和图片预览等替代路径。
- 图片生成或分享错误：日记保持已保存，用户可重新生成或返回。
- 非法或不完整持久化数据：隔离损坏记录，避免应用启动崩溃。
- AI 内容异常：不直接驱动页面导航；流程状态由客户端状态机决定。

## 测试和验收

### 自动化测试

- 领域测试：十五种情绪的 ID、顺序、文案和资产映射。
- 状态机测试：现在分支、过去分支、返回、恢复和完成路径。
- 存储测试：新增、更新、排序、损坏数据和应用恢复。
- 脚本测试：步骤完整、无网可完成、降级后不重复提问。
- 网关契约测试：成功、流式、无密钥、超时、限流、敏感响应和空响应。
- 原生组件测试：导航、输入校验、权限拒绝和错误状态。

### 视觉和真机验收

- 逐页对比 Web 移动视口与 HarmonyOS 截图。
- 验证情绪转盘连续手势、选中态、触觉时机和动画流畅度。
- 真机验证麦克风授权、中文语音识别、图片落盘和系统分享。
- 验证断网、网络切换、后台恢复、字体放大、软键盘和安全区。

### 完成定义

- `apps/harmony` 可由标准 DevEco Studio/Hvigor 流程构建并安装。
- Web MVP 的全部用户流程在 HarmonyOS 端可完成。
- 原始视觉资产被直接复用并可追溯到源文件。
- MiniMax 网关在配置密钥后可运行，未配置或异常时脚本流程可用。
- 自动化测试通过，真机必验功能有记录。
- 权限矩阵、隐私数据流、第三方服务披露和发布检查表齐全。

## 实施顺序

1. 安装 DevEco Studio、HarmonyOS SDK 和模拟器，建立可构建空工程。
2. 建立 Web 行为清单、截图基线和资产清单。
3. 迁移领域模型、状态机、脚本和原生持久化。
4. 按用户流程依次复刻页面与交互。
5. 接入语音、触觉、图片生成和系统分享。
6. 实现 MiniMax AI 网关和客户端流式接口。
7. 完成自动化测试、视觉回归与真机验证。
8. 整理隐私、权限、审核和发布资料。
