# iOS 功能补齐 · 2026-09-30

用户本轮要求从当前鸿蒙源码核查并补齐登录、账号和设置功能。当前分支 codex/ios-specdrive-pilot；所有开发、依赖研究、证据留在 MILO 项目，不启动鸿蒙应用、不修改鸿蒙/Web/网关现有工作。

## 明确范围与验收

1. 首次启动必须展示实际登录页面；验证码/密码切换、忘记密码、返回及输入校验可通过正常入口操作。演示夹具不能作为用户交付入口。
2. 接入官方支持的 AGC iOS SDK 到真实 provider，并执行实际模拟器编译；仅匹配 com.milo.echoes.ios 的本地配置可启用远程认证。不得把鸿蒙配置改名复用、写入服务端凭据或用假登录作为生产后备。验证码登录/自动注册、密码登录、找回密码、账号密码管理、注销需真实SDK实现。缺少iOS配置或账号验证码时保留远程实测阻塞，独立于模拟测试。
3. 密码重置已成功但后续登录失败时，返回密码登录入口并解释密码已更改，不能继续提示重用已消费验证码。验证码目的与邮箱绑定，失败保留重试及输入。
4. 远程退出清理失败仍可退出本机，保留日记和草稿；本机清理失败不能假称成功。注销失败不能误删本机数据；本地账号仍有原 owner 入口。
5. AI默认开关在新建回忆时生效；保存设置后同步当前会话并取消旧配置下请求，迟到结果不能写回。恢复草稿保留其中明确选择，不因初始化或打开设置覆盖。个人模型的Key、同意和账号隔离继续保留。
6. 对照清单列出头像、导出、账号管理、模型预设、连接测试、会员说明的现有与缺失行为；只在有对应产品依据时补齐，不新增未授权支付或云同步。

7. 补齐鸿蒙已有的密码显隐切换；编辑验证码/密码后清除旧错误，保留重置部分成功的明确状态。登录页、账号密码管理都保持原生自动填充和可访问标识。

## 验证方式

- 独立源码差异清单和计划审查先行，最多两轮审查修订。
- 真实AccountModel的注入provider测试覆盖成功、失败、重置部分成功、退出及数据保留；测试provider不得进入生产默认路径。
- 协调器回归覆盖AI默认设置、保存后取消旧请求、恢复草稿；原离线测试保留。
- iOS真实构建、通过普通登录→本地账号→我的→AI设置→保存→重启→退出的UI测试，并对登录/设置关键界面留原图。
- 原生测试执行前停止旧UI test runner并核对当次加载程序来源，避免上轮缓存旧测试包的问题。
- 保留上一轮51/53截图、8/11操作、动效旧包证据及所有失败。此次是用户新增的功能迭代，不重置旧运行，不宣称修复了大字号编辑或完成全53视觉验收。
- 独立功能运行上限每检查3次、相同输入无进展2次、命令90分钟；正式远程邮箱验证作为独立未满足条件列出。当前PR继续draft，全面验收条件未满足不合并。
