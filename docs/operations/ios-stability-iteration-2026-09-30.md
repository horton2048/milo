# MILO iOS 稳定性迭代记录

本轮响应用户在模拟器点击即退出、缺少图标的问题，按已独立审查的三轮计划继续开发。全部源码、状态、派生产物和证据留在当前 MILO 项目；不启动鸿蒙 App，不修改既有用户工作。

## 原因与修复

主机 AMFI 日志确认旧安装包的 ad-hoc 签名携带受限制的 device entitlement，系统在 App 进入业务代码前拒绝执行。上一轮仅回退源码，没有替换已损坏的安装包。本轮使用 Xcode 正常 simulator 签名及生成的 Mach-O simulated entitlement 段，核对签名和编译资产后覆盖安装；没有手工伪造团队权限，也没有卸载 MILO 数据容器。

新增不透明 1024 AppIcon 和可重现生成器，编译产物声明 AppIcon，桌面图标原图已检查。安装会先备份并校验 Documents/Application Support，再比较覆盖前后每个持久文件；最后一次覆盖的 764 个文件内容一致，包含已有 production 账号、草稿、记录。CoreSimulator 的容器 UUID 可在更新时迁移，不能以目录 UUID 变化推断数据丢失。首轮缺少首次迁移前完整哈希，保留这一证据边界。

## 三轮执行

1. 工程诊断和恢复：记录签名拒绝，接入图标、正确签名和可恢复安装检查。首次安装检查错误地要求容器路径不变，修复为备份和逐文件字节核验；原失败记录保留。
2. 第一轮完整运行：账号/Keychain 18/18、账号 UI 3/3；十次冷启动成功，但背景状态观测失败；journeys 9/11（两项卡片边界）；motion 1/2；capture 50/53（两项 XCTest 拖动超时、一项大字号外层滚动跨度）。真实大字号输入末句已通过。所有运行加载正确测试二进制，未把历史旧 runner 的结果作本轮依据。
3. 修复后回归：卡片模板区域增加实际 8pt 余量；使用 UITextView 控制编辑与光标可见；后台监测采用 SpringBoard 前景和独立 App 状态等待；截图拖动减少持续按压，异常跳跃执行有限修正并另存诊断原图。原有间距、末句、背景暂停恢复和滚动覆盖断言均保留。第二次完整采集 52/53 后，最后诊断确定 196pt 编辑视口每步实际仅推进约 104pt，60 图时到 5335/7727。仅编辑器向前手势扩大到 0.88 视口，原 0.9 视口+1pt、60 图、字号和内容仍不变，再进行第三次完整原生回归。
